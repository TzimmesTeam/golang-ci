# Как пользоваться

Заполните `docs/release/v1.2.3.md` — это тело релиза для тега `v1.2.3`. Вместо `v1.2.3` укажите свою версию и в имени файла, и в командах ниже.

```sh
cp docs/release/template.md docs/release/v1.2.3.md
```

```sh
git add docs/release/v1.2.3.md
git commit -m "Описание релиза v1.2.3"
git push origin HEAD
git tag -a v1.2.3 -m "Здесь укажите заголовок релиза"
git push origin v1.2.3
```

Заголовок берётся из сообщения `tag -m`, тело — из Markdown в коммите тега. Изменения приложения должны быть закоммичены до создания тега. Для предварительного релиза используйте версию вида `v1.2.3-rc.1`.

Что выполняет CI:

- **Линтеры:** ресурсы, контексты, ошибки, безопасность, лишние аллокации и копирования. Когнитивная сложность — от 20, цикломатическая — от 15. Без требований к комментариям и стилю. Статический анализ не заменяет профилирование утечек.
- **Тесты:** `-race -shuffle=on -count=1`; если тестов нет — пропуск.
- **Сборка:** все Go-пакеты и контейнеры `linux/amd64` и `linux/arm64`. Контейнеры собираются параллельно проверкам, каждая архитектура — на отдельном runner. Бинарник собирается с `CGO_ENABLED=0`, `-trimpath`, `-ldflags="-s -w"`; образ — `scratch`, без root, с SBOM и provenance.
- **Публикация:** только по тегу и после успешных проверок — образ `ghcr.io/<owner>/<repo>:<тег>` и GitHub Release.

Без `go.mod` Go-задачи пропускаются; без `main` пропускаются контейнеры. Задачи разнесены по файлам в `.github/workflows/`, зависимости задаёт `ci.yml`. Dependabot проверяет обновления Actions еженедельно; версия golangci-lint задана в `lint.yml`.

Кеши Go разделены между линтером, тестами и сборкой. Docker кешируется отдельно для каждой архитектуры; публикация использует готовые слои. Проверка зависимостей выполняется один раз, повторный vet в тестах отключён — его выполняет golangci-lint.
